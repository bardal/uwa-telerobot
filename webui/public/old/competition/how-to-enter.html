Introduction

Part of what we do here is research on what is the best method to tackle certain tasks or more realistically, the most popular choices. For this we encourage user feedback so that we may implement peoples ideas and possibly develop a more favourable relationship between person and machine. In the end, people still have to use the interface.

We are preparing to take it one step further by allowing the public to design their own interfaces for interaction with the robot server. We will observe which of these interfaces seem to be the more popular, ask the question why, and then draw some sort of conclusion as to what people look for in an ideal interface.

Points under consideration are:

  • How much is crammed onto a page at any one time
  • How much scrolling is necessary
  • Which options are frequently used and so should not be placed in an obscure position
  • Is the "Move Robot" button in a convenient position

How the template works.

When a robot move or a request for control of the robot has been made, a HTML page is returned indicating the success of the request. The layout of the returned page is determined by the relevent template. The template file is copied to the output with the values of such fields as position and image attributes inserted into it, the result being the page as seen by the users. This means that the template (when viewed with a browser) is almost identical to the pages that users get sent to them but instead of containing numbers, contains labels that indicate where these numbers are meant to go. Some of these fields are meant for text as well.

The idea is then to design the template such that it has a convenient layout because the pages that people will eventually see will be structured the same way. The layout you design can be previewed by viewing it through a browser locally.

The javascript section that appears before the main body of the HTML document should not be changed without good reason. You may find that javascript can be a very powerful tool in enhancing the visual structure of the interface but should be used with caution. If you are not familiar with it, we recommend that you omit it altogether and then we will add it again at our end. Java Applets should not be used at all.

Templates

As a starting point we suggest that you investigate the default templates. Save them using your browser so that you can examine the HTML coding.

There are several critical components in a template (ie, don't leave them out). Firstly, take note of the form tags and their placement. If fields aren't contained within the form tags they will not get submitted. Secondly, the hidden fields that specify the OperatorID and SessionID. It is these numbers that allow for the same user to keep control. When a new operator first gains control, they are assigned an OperatorID and the robot program uses this ID to determine whether or not it should execute a submitted request.

If any of the form fields are missing, default values will be used by the robot move program and so will restrict what can be done. If labels are omitted, details concerning the position of the robot and other useful information may not be displayed. Most critical are that the Operator Details labels are included or the operator will not be able to keep control beyond 1 move.

Once you are happy with how the pages seem to appear (using Netscape on your local machine) you can submit the HTML document by filling the above form. Enter the full pathname of your source file in the File box (or browse your local disk) and the stem of what you want the file to be called on our machine. We suggest using your name as a file stem (eg, joeoprtr.htm). For your templates to work properly they should all have the same name - each type (observer, operator etc) is saved in different directories so don't worry about overwriting them. This enables the telerobot code to pick the right template when you change from observer to new operator or vice versa . If you do not specify one, a default name will be allocated - this is not recommended. Also make sure that you have correctly indicated the type of template you are submitting.

Once you have submitted your file it shouls be available immediately. You can use it by going to the interface selection part of the page and enter the stem of the file name in the text box on the right (eg, joeoprtr). If you enter the name of the file incorrectly or the file does not exist, the default page will be returned.
