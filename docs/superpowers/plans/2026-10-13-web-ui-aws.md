# Web UI and AWS Deployment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the February 2000 TA200001 telerobot interface on the public web.
It is a faithful TypeScript recreation that talks to the unchanged 2000 Java
servers through a new gateway. It runs wake-on-demand on AWS, with an S3
archive and a History page.

**Architecture:**
* **Lab:** MOM, VirtualLab and RobotProxy run as they do today, but on Java
  21 and bound to 127.0.0.1.
* **Gateway:** a Java 21 Jetty WebSocket gateway is the only public port. It
  logs each browser into MOM as an ordinary client.
* **UI:** a Vite/TypeScript UI is served from S3 through CloudFront.
  CloudFront also routes `/api/*` to a status/wake Lambda and `/ws` and
  `/healthz` to the EC2 instance.
* **Build:** everything deployed is built from this repo's source, in a
  clean clone.

**Tech Stack:**
* Java 8 source level for the existing `lab` module, run on Java 21.
* Java 21 for `gateway`, with Jetty 12, Jackson 2 and nimbus-jose-jwt.
* The AWS SDK for Java v2 (s3, ssm, ec2), with the url-connection HTTP
  client.
* TypeScript 5 with Vite, vitest, Playwright and eslint.
* AWS CDK v2 (TypeScript) and Node 22 Lambda.
* Amazon Linux 2023 with Corretto 21 and systemd.

**Spec:** `docs/superpowers/specs/2026-10-13-web-ui-aws-design.md`. Read it
first; this plan argues from it.

## Decisions since the spec (binding; the spec's Amendments section records them)

1. **No Docker or ECR.** Docker Desktop isn't running on the build machine,
   and a container adds nothing that systemd hardening doesn't give us.
   * The instance installs `java-21-amazon-corretto-headless` and pulls
     `lab.jar` and `gateway.jar` from a private artifacts bucket.
   * It runs four systemd units as user `telerobot`, with
     `ProtectSystem=strict`, `NoNewPrivileges`, `PrivateTmp` and
     `ReadWritePaths=/var/lib/telerobot`.
   * MOM, VirtualLab and RobotProxy bind 127.0.0.1. The security group only
     admits 8080 from the CloudFront prefix list.
2. **The Lambda function URL is protected by the origin secret header**, not
   OAC. That avoids OAC's SHA-256 payload-hash requirement for POST.
3. **The reaper owns the running-hours counter and the heartbeat check.**
   * The gateway writes `/telerobot/heartbeat` (JSON
     `{time, sessions, lastSessionEnd, commit}`) to SSM every 60 s.
   * Every 15 min, while the instance is running, the reaper:
     * adds 15 to the integer parameter `/telerobot/minutes/<YYYY-MM>`;
     * stops the instance if the heartbeat is more than 5 min old, or if
       `sessions == 0` and `lastSessionEnd` is more than 15 min ago.
   * The gateway's own idle stop remains as the first line.
4. **Built from source.** `deploy/deploy.ps1` clones the committed `HEAD` into
   a temp directory and runs `mvn -B clean verify` there, with all tests. It
   uploads those jars, stamped with the commit hash: the manifest gets
   `Implementation-Version`, and `/healthz` reports it. Nothing from
   `~/code/UWATelerobot` or any prebuilt binary is ever used.
5. **Pending Barney's own accounts.** The first deploy uses Turnstile's
   always-pass test keys and email-only Cognito sign-in.
   * Google sign-in turns on when `googleClientId` and `googleClientSecret`
     CDK context values are supplied.
   * Real Turnstile keys are two SSM parameters.
   * The handover report says so.
6. **CloudFront flat-rate Free plan:** `deploy.ps1` tries to subscribe with
   `aws pricingplanmanager` after the stack deploys. If it fails (for
   example, the account already has its 3 Free distributions), the
   distribution stays pay-as-you-go with the WAF web ACL, at about $8 a
   month.
7. **Dev mode** (`--dev`, never on AWS):
   * The gateway serves `webui/dist`, `/api/status` (always running) and
     `/archive/public/*` from a local directory.
   * It accepts `hello.dev = {sub, groups}` instead of a Cognito token, and
     Turnstile test keys.
   * Its archive store writes to the file system.
   * A test proves production mode rejects `hello.dev`.

## Global Constraints

* The existing 2000 code stays buildable on JDK 8 with source/target 1.8, and
  the local applet route (`start.ps1`, `start.sh`, `appletviewer`) keeps
  working.
* `gateway` is Java 21. The servers run on Java 21 in production.
* The repo is going public: no secrets, accounts or personal email
  addresses in it. Secrets come only from SSM.
* Origin secret header name: `X-Telerobot-Origin`.
* Message limits:
  * Each incoming message is at most 4 KB.
  * Path scripts are at most 400 characters and 30 waypoints, with at most 4
    commands queued per session.
  * Chat messages are at most 300 characters, at 1 a second with bursts of
    5.
  * Workspace points: at most 20 per user.
  * Snapshots: at most 10 per user per hour.
  * A session with 20 rejected messages in a minute is closed.
  * `activity` messages: at most 2 a second.
* Session limits:
  * A session with no human input for 10 minutes is closed; every session
    closes after 2 hours.
  * The gateway stops its instance 15 minutes after the last session.
* Global caps: 60 viewers, 4 connections per IP, and 10 handshakes a second.
* Wake cap: 150 hours a month (CDK context `hoursCap`). Budget: $20 a month,
  with an alert at 50% and 100%.
* Archive cap: 5 GB, then images stop being saved; chat continues.
* MOM service accounts:
  * `guest` (UserLevel Guest, PIN -1).
  * `registered` (UserLevel Registered) and `admin` (UserLevel Team), with
    random PINs from SSM.
  * The existing `robot` and `camera` accounts get random PINs from SSM on
    AWS.
* Serialization filter (`jdk.serialFilter`) on MOM, VirtualLab and
  RobotProxy:
  `au.edu.uwa.mech.**;Jama.**;java.lang.*;java.util.*;java.awt.Point;java.awt.Rectangle;[*;!*`
  This exact string is the constant `SerialFilter.PATTERN`.
* UI copy:
  * The original menu labels, including "Comand from cursor".
  * Salmon background `#DC8C64`.
  * Waking page: "Turning the robot on…".
  * When the hours cap is reached: "The robot is resting until next month".
* AWS region: eu-west-2. The WAF web ACL goes in us-east-1. CDK is already
  bootstrapped in both.

## Review Focus

1. **Two browsers with the same nickname.** MOM keeps a killed client's
   nick, so the gateway must make nicks unique: it appends `~2`, `~3` and so
   on, and tells the client its real nick in `welcome`. Pinned in Task 5.
2. **A browser tab closed in the middle of a command, or while holding
   control.** The gateway must release the token and log out of MOM so the
   next user isn't blocked for 180 s. Pinned in Task 5.
3. **The lab restarting while a page is open.** The UI must show the wake
   page and reconnect, not freeze on the last image. Pinned in Task 13.
4. **A tiny or very wide window.** The canvas must scale both ways, and
   dragging must stay on target at any scale. Pinned in Task 10 (unit) and
   Task 14 (e2e).
5. **Non-ASCII and hostile text** in nicknames, chat and scripts (`<script>`,
   RTL marks, emoji, `../`). It must render as text, never reach storage
   keys, and nicks are restricted to `[A-Za-z0-9 _.-]{1,20}`. Pinned in
   Tasks 3, 6 and 13.

## Streams and order

Each stream runs in its own git worktree and branch, so streams never share
files. Stream A is `web-ui` in the main checkout. Stream B is `web-ui-ui` in
`../uwa-telerobot-ui`, and Stream C is `web-ui-deploy` in
`../uwa-telerobot-deploy`. Streams B and C merge into `web-ui` before Task
17. Within a stream, tasks run strictly in order.

* **Stream A (Java):** Tasks 1–8, in order.
* **Stream B (UI):** Tasks 9–14. Task 9 needs Task 1's fixture generator.
  Task 14 needs Tasks 7 and 13.
* **Stream C (AWS):** Tasks 15–17. Task 17 needs everything.

Streams A, B and C can run in parallel in separate worktrees, merged into
`web-ui` after each task's review. The shared contract is **the message
protocol below**: it is normative, and both sides implement it exactly.

## Message protocol (normative)

**JSON text frames.** Every message has `"t"`, its type. Unknown `t` values or
unknown fields are rejected with `bad-message`.

**Browser → gateway:**

```ts
type In =
 | {t:"hello", nick:string, turnstile?:string, idToken?:string, dev?:{sub:string, groups:string[]}}
 | {t:"command", script:string}
 | {t:"takeControl"} | {t:"release"}
 | {t:"chat", text:string}
 | {t:"selectCamera", camera:string}
 | {t:"cameraSettings", camera:string, on:boolean, width:number, height:number, zoom:number, quality:number, fixed:boolean}
 | {t:"newImage", camera:string}
 | {t:"workspaceAdd", x:number, y:number, z:number, label:string}
 | {t:"workspaceDelete", id:string}
 | {t:"archiveImages"}
 | {t:"activity"}
 | {t:"admin", action:"kick"|"ban"|"reset"|"deleteMove"|"deleteSnapshot"|"deleteChat", nick?:string, id?:string}
```

**Gateway → browser:**

```ts
type Out =
 | {t:"welcome", nick:string, level:"guest"|"registered"|"admin", cameras:string[], commit:string,
    limits:{script:number, waypoints:number, chat:number}}
 | {t:"robotState", x:number, y:number, z:number, spin:number, tilt:number, gripperOpen:boolean, moving:boolean}
 | {t:"controller", nick:string|null}
 | {t:"commandStatus", id:string, state:"queued"|"sent"|"done"|"error", script:string, text:string}
 | {t:"users", nicks:string[]}
 | {t:"chat", id:string, nick:string, text:string, time:number}
 | {t:"workspace", points:{id:string, x:number, y:number, z:number, label:string, owner:string}[]}
 | {t:"image", camera:string, seq:number, width:number, height:number, calibration:number[]}
 | {t:"cameraSettings", camera:string, on:boolean, width:number, height:number, zoom:number, quality:number, fixed:boolean}
 | {t:"archived", kind:"move"|"snapshot", id:string, url:string}
 | {t:"lab", state:"ready"|"stopping", message:string}
 | {t:"console", text:string}
 | {t:"error", code:"bad-message"|"rate-limited"|"not-in-control"|"unauthorised"|"lab-unavailable"|"too-many", message:string}
```

**Details:**

* An `image` message is always followed immediately by one binary frame
  holding the JPEG.
* `calibration` is the 3×4 matrix in row-major order, 12 numbers, as
  received from the camera server.
* Angles are in degrees, as in `Pose3d.toDisplayString`: spin is the GBH
  `s` and tilt is `t`.
* Times are epoch milliseconds.

**HTTP:**
* `GET /healthz` returns
  `{"ok":true,"sessions":n,"commit":"<sha>","lab":"ready"}`.
* `GET /ws` upgrades to the WebSocket. It requires that:
  * the `Origin` is in the allowed list (`--allowed-origin`, repeatable);
  * outside dev mode, the `X-Telerobot-Origin` header equals the secret.

### Task 4: Auth

**Files:**
* Create:
  * `web/Auth.java`;
  * `web/Turnstile.java` (an HTTP client for
    `https://challenges.cloudflare.com/turnstile/v0/siteverify`, using

    ipHash)`, where `Level` is `GUEST`, `REGISTERED` or `ADMIN`.

**Interfaces:** `Auth(GatewayConfig cfg, Turnstile ts, JWTProcessor<SecurityContext> jwt)`
with `Identity authenticate(In.Hello h, String remoteIp) throws Unauthorised`.

* **idToken:** process it with nimbus `DefaultJWTProcessor`, using a remote
  JWK set from `<issuer>/.well-known/jwks.json` (cached by nimbus), RS256,
  and `DefaultJWTClaimsVerifier` requiring:
  * `iss` equals the issuer;
    * `aud` is one of the configured client ids (`cfg.cognitoClientIds()`, a

### Task 15: Status, wake and reaper Lambda

**Files:**
* Create:
  * `deploy/lambda/index.ts` (one handler that routes `GET /api/status`,
    `POST /api/wake` and the scheduled event);

  * `deploy/lambda/core.test.ts`;

**Interfaces:**
* `status(deps)` returns `{state, healthy, commit}`, where `healthy` means
  the heartbeat is no more than 90 s old.
* `wake(deps, body, headers)` returns `{status, body}`:
  * 403 if the `x-telerobot-origin` header is wrong;
  * 400 for an invalid body;
  * 401 if the proof fails (Turnstile verify, or a Cognito ID token checked
    with `aws-jwt-verify`, exact version);
  * 429 `{reason:"cap"}` if this month's minutes are at or over
    `hoursCap * 60`;
  * otherwise `StartInstances` and 202.
* `reap(deps)`: if the instance is running, add 15 to
  `/telerobot/minutes/<YYYY-MM>` (UTC month), then stop it if the heartbeat is stale (over 5 min) or idle
  (`sessions==0` and `lastSessionEnd` over 15 min ago).
* Deps: `ec2` (`describeState`, `start`, `stop`), `ssm` (`get`, `put`),
  `verifyTurnstile`, `verifyIdToken`, `now`, `instanceId`, `hoursCap`.
* The SDK is `@aws-sdk/client-ec2` and `@aws-sdk/client-ssm` (exact
  versions), bundled by CDK `NodejsFunction` with esbuild.
